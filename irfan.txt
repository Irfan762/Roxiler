Build a complete production-ready **Store Rating Web Application** based on the following requirements.

## Tech Stack

Use:

- Frontend: Next.js + TypeScript
- Styling: Tailwind CSS
- UI: Clean, modern, responsive dashboard UI
- Forms: React Hook Form + Zod
- Backend: Node.js + Express.js + TypeScript
- Database: PostgreSQL
- ORM: Prisma
- Authentication: JWT
- Password hashing: bcrypt

Use a clean and scalable folder structure. Follow frontend and backend best practices.

---

# 1. User Roles

The application must support exactly three roles:

1. SYSTEM_ADMIN
2. NORMAL_USER
3. STORE_OWNER

There must be **one common login page** for all users.

After login, redirect users according to their role:

- SYSTEM_ADMIN → Admin Dashboard
- NORMAL_USER → Store Listing
- STORE_OWNER → Store Owner Dashboard

Implement proper role-based authorization on the backend. Never rely only on frontend role checks.

---

# 2. Authentication

Create:

### Login

Fields:

- Email
- Password

### Normal User Signup

Fields:

- Name
- Email
- Address
- Password

Only NORMAL_USER should be able to register through the public signup page.

Admins can create:

- Normal users
- Admin users

Admins can also create stores.

Implement:

- JWT authentication
- Protected routes
- Role-based middleware
- bcrypt password hashing
- Logout
- Change password
- Proper authentication error handling

Never store plain-text passwords.

---

# 3. Validation

Implement validation on both frontend and backend.

### Name

- Minimum: 20 characters
- Maximum: 60 characters

### Address

- Maximum: 400 characters

### Password

- Minimum: 8 characters
- Maximum: 16 characters
- At least one uppercase letter
- At least one special character

Example:

`Password@123`

### Email

Must follow standard email validation rules.

### Rating

Rating must be an integer from:

`1 to 5`

Backend must reject invalid ratings even if frontend validation is bypassed.

# 4. Database Design

Use PostgreSQL with Prisma.

Create these tables/models:

## User

Fields:

- id
- name
- email
- passwordHash
- address
- role
- createdAt
- updatedAt

Email must be unique.

Role should be an enum:

- SYSTEM_ADMIN
- NORMAL_USER
- STORE_OWNER

## Store

Fields:

- id
- name
- email
- address
- ownerId
- createdAt
- updatedAt

ownerId should reference the STORE_OWNER user.

## Rating

Fields:

- id
- userId
- storeId
- rating
- createdAt
- updatedAt

A user can submit only ONE rating for a particular store.

Create a unique constraint:

`userId + storeId`

A user can update their existing rating.

Calculate overall store rating using the ratings table rather than storing a duplicate rating value unless there is a strong reason to cache it.

Add appropriate indexes for:

- email
- name
- address
- role
- store name
- store address
- rating relationships

# 19. Important Development Rule

Before coding:

1. Analyze all requirements.
2. Design the database schema.
3. Create the project structure.
4. Implement backend authentication.
5. Implement role-based authorization.
6. Implement APIs.
7. Implement frontend.
8. Connect frontend with backend.
9. Add validation.
10. Add search/filter/sorting/pagination.
11. Add security.
12. Add tests.
13. Run the application and fix all errors.

Do not skip requirements.

Do not create fake/mock functionality where a real database implementation is required.

Do not leave TODOs for core functionality.

The final application should be fully functional from signup/login → dashboard → store listing → rating → admin management → store owner dashboard.

At the end, provide:

1. Complete project structure
2. Database schema
3. API list
4. Setup commands
5. Test credentials
6. How to run frontend
7. How to run backend
8. Any assumptions made
9. Any remaining limitations
